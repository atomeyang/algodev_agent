[Title] 算法研发 Agent 优化方案与架构
[Subtitle] 设计版本 v0.4  |  自主子 Agent 与受约束研发闭环  |  2026 年 10 月 8 日
[Normal] 本方案在设计 v0.2 基础上，复用 Codex 与 DeepSeek 的自主工作能力，由 LangGraph 管理研发生命周期。外层掌握阶段、批准范围、预算、资产版本和验收，子 Agent 在明确任务内自主研究、设计、编程和调试。当前为待实施设计，不是已发布软件。
[Heading 1] 1 目标与主要变化
[Normal] 用户通过文本描述算法功能、输入输出、ROM、计算量、部署条件和效果要求。系统完成前沿调研、联合模型与数据设计、方案确认、执行计划、方法池、数据构建、实验调优、评测和文档归档，并支持外部测评问题驱动下一轮优化。
--- TABLE ---
变化 | v0.4 的设计
自主工作单元 | 第一版只设研究设计与 Codex 编程两个核心子 Agent；本地辅助模型通过工具调用。
三个循环 | 研发决策、编程修复、批量实验分别运行，各自有边界和预算。
证据服务 | 新增 evidence_runtime，管理来源、证据包、定向补读、差异和缓存。
方案范围批准 | 一次批准可覆盖限定的候选、配方、搜索空间与资源预算，超范围返回规划。
上下文管理 | 子 Agent 有独立任务会话；跨角色交接使用结构化契约和证据引用。
可验收实施 | CLI、恢复、归档、版本和成本机制通过实际用例验证，不能只依赖提示词。
--- END TABLE ---
[Heading 2] 价值与适用范围
[Normal] 系统价值来自重复研发中的管理负担减少、统一评测与可追溯证据。相同模型和数据条件下，不保证方案质量自动高于直接使用工具；证据组织、必要的自由探索和可靠实验反馈才是质量基础。平台也带来开发及维护成本，应先验证单业务闭环。
[Heading 2] 工具和模型定位
[Normal] DeepSeek Flash 作为主要研究设计模型，结合搜索与资料读取形成子 Agent；Codex 是编程执行器，保留其读代码、修改、运行和修复的自主循环。Qwen3.8-27B 等本地模型用于资料提取、标注辅助和诊断。服务标识、能力与版本在配置中管理，实施时核对兼容性。

[Heading 2] 保持内层自主性
[Normal] 给研究 Agent 一个完整的研究与设计目标，允许检索、补读、比较和质疑假设。给 Codex 一个完整的编程目标，允许自行阅读仓库、修改、测试和修复。外层在任务交接点验收，避免将每条命令和每次编辑都拆成图节点。
[Normal] Runner 与 Evaluator 根据固定配置执行。指标计算、哈希、作业登记和验收判断由程序完成；云端解释复杂结果与设计下一步。评测结果回流到证据服务，再供新计划使用。
[Heading 1] 3 自主子 Agent 的输入输出
[Heading 2] 研究设计子 Agent
[Normal] 输入：TaskSpec、当前批准范围、EvidencePacket、历史决策和剩余预算。工具：检索公开来源、读取资料片段、获取代码与配置、查询评测、请求本地诊断。输出：ResearchReport、候选方案、PlanSpec、改进假设、可比较条件、不确定项及继续或停止建议。
[Normal] 前沿调研解释方法原理并给出论文和开源实现链接，记录 commit、权重、许可、训练测试条件和复现状态。公开最好效果、本地高容量参考与约束内最佳结果分别说明。论文数字不能无条件视为业务效果或已证明的理论上限。
[Heading 2] Codex 编程子 Agent
[Normal] 输入：批准计划哈希、完整目标、基线 commit、隔离工作区、允许修改路径和外部验收命令。工具：文件、终端、依赖及短时验证。输出：CodingResult、代码版本、实际 diff、依赖变化、验证证据、剩余问题和必要的方案变更请求。
[Normal] 编程子 Agent 可以自主修复实现问题。需要更换算法方向、改变数据来源、修改冻结评测或增加预算时提交 change_request，回到研发规划。长训练交给 Runner；短时验证长度和资源在任务契约里规定。
[Heading 2] 上下文与会话
[Normal] 为角色和任务登记独立会话，键包含 task_id、角色、计划或编程任务、基线版本。继续同一目标可复用会话；上下文不兼容时创建新会话并导入必要摘要。LangGraph 只保存会话 ID、状态、摘要和资产引用，不复制所有对话。
[Normal] 跨角色交接使用结构化契约，不共享无限聊天历史。研究 Agent 可以定向读入代码或日志，Codex 可查询必要证据；工具检查上传范围和预算。会话状态不能作为资产版本的替代。
[Heading 2] 终止与结果标准
[Normal] 每个子 Agent 都有工具步数、时间、Token、修复次数和可读写范围。结果区分 completed、needs_plan_change、blocked、failed。完成表示交付满足该任务契约，最终业务达标仍由独立评测确认。
[Heading 1] 4 三个循环与方案批准
--- TABLE ---
循环 | 控制者与终点
研发决策循环 | LangGraph 调用研究设计 Agent；依据评测和外部反馈生成新假设与计划，达标、停止或等待输入时退出。
编程修复循环 | Codex 内部完成读代码、实现、短时测试与修复；交付、需变更方案或达到限制时返回。
批量实验循环 | Runner 或参数搜索器执行批准范围内的配置、消融和早停；批次完成后汇总，不逐次重做规划。
--- END TABLE ---
[Heading 2] 研发流程
[Normal] 需求解析并创建任务 → 实际调研与证据登记 → 一至三种候选及联合数据方案 → 用户确认执行范围 → 编程实现与归档 → 数据和实验批次 → 候选模型登记 → 验证集评测与资源测量 → 复杂分析与下一轮决策。
[Normal] 批次结束后，云端可设计下一轮。参数微调和实现修复在范围内自动执行；新的方案超出原批准范围时展示具体变更、预算和证据，再确认新计划。用户也可选择每轮确认模式。
[Heading 2] 批准范围
[Normal] 批准记录绑定任务、计划 ID、内容哈希、状态版本和执行范围。范围包含候选方法、允许的数据配方变化、参数空间、最大资源与迭代数、冻结评测版本、允许的代码路径和上传规则。修改这些内容导致相应批准失效。
[Normal] 范围判断由程序比较，研究 Agent 或 Codex 可以提出变更但不能自行扩大权限。任务启动时解析固定资产版本，后续聊天不改变正在运行的训练。
[Heading 2] 停止与恢复
[Normal] 达标后进行独立最终验收和交付。预算耗尽、连续无提升、资料不足或找不到可行方案时保存最优候选与原因，进入可恢复状态。暂停和取消分别控制阶段启动与具体作业，退出 CLI 只脱离交互。
[Normal] 恢复时对账检查点、待执行事件、作业登记、实际进程和产物。幂等键、持久化队列及可查询的提交标识防止重复执行；不能只凭流程检查点宣称所有副作用恰好执行一次。
[Heading 1] 5 证据服务与云端成本
[Normal] 云端承担复杂研究、设计、思考、规划及评测解释。节约成本通过控制重复和无关上下文实现，同时保持云端读取关键证据的能力。证据服务不替云端预先排除重要假设。
--- TABLE ---
能力 | 实现约定
来源登记 | URL 或本地引用、访问时间、定位、版本、许可、内容哈希和适用范围。
证据包 | 当前需求、方案、基线、指标变化、切片、代表失败、反例、不确定项、资源和待决问题。
定向补读 | 先给索引和摘要；按证据引用及片段范围读取，必要时补充样例或配置。
差异与缓存 | 明确基线后传变化；按需求、证据、代码、数据、协议、模型与提示词版本缓存。
本地诊断 | 确定性统计与模型辅助分类相结合，检查摘要证据覆盖，保留来源。
成本账本 | 设计、分析和编程分别登记实际 usage 与费用；缺项标记未知或估算。
--- END TABLE ---
[Heading 2] 上传边界
[Normal] 原始数据、完整日志和整个仓库默认留在本地。云端可以读取必要原文、代码和样例；所有读取经工具层控制。Codex 编程时读入的源码也可能产生云端 Token，必须计入预算。文档状态、目录查询和普通训练进度不调用云端。
[Heading 2] 触发与质量检查
[Normal] 首轮深度研究、批次结束、新外部问题、重大回归、停滞和证据冲突触发复杂调用。普通 epoch 与每次参数试验不触发。证据包须同时呈现支持与反例；来源无法追溯、关键切片缺失或测量条件不一致时明确标记。
[Normal] 调用前估算并预留预算，调用后按实际用量结算。支持输出长度、工具读取大小、修复次数和批次资源限制；不承诺未经实测的固定节省百分比。

[Heading 2] 业务任务组织
[Normal] 任务根放 task.yaml 与 OVERVIEW.docx。plans 保存方案及批准；model_pool/<method> 保存完整方法代码、配置和初始权重；data 保存只读 raw、recipes、splits、releases/train、val、test 和方案及迭代记录。
[Normal] coding_records 保存编程归档；runs 保存实验配置、日志和检查点；model_versions 保存模型清单；evaluation 保存协议、脚本和结果分析；feedback 保存外部问题；docs/research 与 docs/iterations 保存单次报告；deliverables 保存最终版本。总览随迭代更新并引用单次文档。
[Heading 2] 业务插件
[Normal] 插件校验需求和数据，定义允许的处理、指标、失败切片与部署口径；方法适配器提供 prepare、train、predict、export、profile 和 capabilities。无需训练的传统算法跳过训练；大数据和权重可使用可解析引用。
[Heading 1] 6.1 LangGraph 源码与模块边界
[Normal] 平台代码与任务实验目录同级。LangGraph 流程源码由本项目维护；官方 LangGraph 和 LangChain 作为锁定依赖安装，不复制框架源码。流程节点只承担阶段交接和控制，研究与编程子 Agent 保留内部自主循环。
--- TABLE ---
相对 agentic_algorithm 的位置 | 职责
agent_runtime/src/algo_agent/graph/ | state.py 状态和更新规则；builder.py 建图与编译；routing.py 条件路由；checkpoints.py 检查点适配；nodes/ 阶段节点。
agent_runtime/src/algo_agent/agents/ | research_design.py 研究设计循环；codex_coding.py 编程任务调度与交接。
agent_runtime/src/algo_agent/service/ | controller.py 处理启动、批准、暂停、恢复和用户命令。
agent_runtime/src/algo_agent/schemas/ 与 storage/ | 统一契约、资产登记和事务接口；其他 runtime 调用这些接口。
agent_runtime/configs/ | workflow.yaml 流程默认配置；provider、预算与上传策略。
runtime_state/ | 检查点数据库、事件、作业、会话映射、资产索引及账本；不存放流程源码。
--- END TABLE ---
[Heading 2] 节点与外部模块
[Normal] nodes/ 包含 intake、research、design_plan、approval、coding、experiments、evaluation、analysis、feedback 和 export_docs。coding_runtime 提供 Codex 工具适配；execution_runtime 提供作业和资源执行；evidence_runtime 提供证据读取。Evaluator 使用冻结协议独立计算结果。
[Normal] 共享组件源码放 algorithm_plugins/common/，业务专用实现放 algorithm_plugins/<domain>/；可复用配置、方案和资产引用放 shared_assets/。同一组件只有一个规范实现，任务方法池通过版本引用复用，避免多份源码漂移。
[Heading 1] 6.2 技术和方案资产沉淀
[Normal] 每次实验先保留完整任务记录；复用价值经过验证后，再发布共享资产。系统沉淀组件、方案配方及失败经验，目标是让后续任务可以检索、执行并验证历史能力。DOCX 用于阅读和审查，机器读取结构化清单。
--- TABLE ---
资产类型 | 规范位置与发布条件
组件 | algorithm_plugins/common/ 或业务插件；有明确接口、版本、依赖、测试及适用输入。
方案配方 | shared_assets/recipes/<asset_id>/<version>/；recipe.yaml 与 RECIPE.docx 配套，绑定模型、数据、训练、评测及部署依赖。
数据和模型 | shared_assets/datasets/ 与 models/；保存授权范围、不可变清单、哈希及可解析引用。
评测模板 | shared_assets/evaluation/；描述指标口径、场景切片与设备条件，不共享私有最终测试样本。
失败经验 | shared_assets/knowledge/；保存条件、反例、原因置信度、证据和复现状态，不将一次失败泛化为普遍结论。
--- END TABLE ---
[Heading 2] 统一资产登记
[Normal] AssetRegistry 使用现有 storage 层，索引存放 runtime_state/；资产正文与清单位于上述规范目录。登记 asset_id、asset_version、asset_type、schema_version、来源任务、适用条件、依赖、证据、许可证、状态和最近验证时间。登记服务通过公开接口供研究、执行和文档模块调用。
[Normal] 状态为 researched、reproduced、business_validated 或 reusable；只有通过发布检查的资产进入 reusable 检索默认集合。失效或撤销通过新事件与 deprecated 标记记录，历史引用仍可解析。共享只是位置；可复用状态必须有验证依据。
[Heading 2] 复用前检查
[Normal] 先比较新任务的输入输出、业务分布、质量门槛、硬件、资源、协议、依赖和授权；输出 compatible、adaptation_required、incompatible 或 unknown。unknown 不视为通过。研究 Agent 根据检查和证据选择直接复现、调整或重新研究；执行前仍绑定当前任务计划和批准范围。
[Heading 1] 6.3 复现与迁移能力
[Normal] 可复用方案提供最小复现包：不可变 manifest、recipe、依赖锁、数据或可解析引用、权重校验和、运行入口、评测入口、预期结果与允许误差、目标设备和环境说明。离线 CPU 演示与业务复现明确区分。
--- TABLE ---
迁移场景 | 复用范围与必要验证
同业务新数据 | 复用方法和插件；检查分布、划分、标注与质量变化，重新评测。
跨领域业务 | 复用流程、预算、证据、版本和文档；新建业务数据、指标与方法适配。
更换模型服务或编程工具 | 保留统一契约；验证工具调用、结构化结果、用量和恢复语义。
更换机器或硬件 | 重建锁定环境和路径映射；重新测量内存、ROM、计算量与延迟。
升级流程或状态格式 | 版本化 graph、schema 和数据库迁移；先备份，校验恢复，保留回退路径。
--- END TABLE ---
[Heading 2] 迁移包与恢复边界
[Normal] 导出任务清单、必要代码和配置、资产依赖闭包、文档、校验和及不含凭证的路径映射。外部大文件提供受控引用或单独转移。导入先验证哈希和依赖，再分配本地路径；资产 ID 与原始来源保留，记录目标环境和导入事件。
[Normal] 默认在安全阶段边界迁移。活跃 GPU 作业与云端会话不能保证直接迁移；未支持时保存检查点、停在可恢复状态并创建新运行。原始实验记录保持不变，新环境执行产生新 run_id，不覆盖旧结果。
[Heading 2] 新增验收与版本说明
[Normal] v0.4 明确 LangGraph 代码、资产索引和官方依赖的边界；增加共享资产发布、兼容性检查、最小复现包与迁移要求。验收至少包含跨任务复用、依赖失效、引用失效、授权拒绝和跨目录导入。对应开发指导 v1.2；历史文档保留。
[Normal] 这些是待开发能力，当前仅完成设计文档。资产复用减少重复开发，但收益需要真实任务验证，不能由归档数量或模拟结果证明。
[Heading 1] 7 版本 评测与外部反馈
[Heading 2] 完整证据链
[Normal] 需求版本 → 调研证据 → 批准计划 → 编程记录与代码版本 → 数据版本 → 实验运行 → 模型版本 → 评测结果 → 决策。每个产物有 ID、schema_version、来源引用和必要哈希，不覆盖历史最佳权重。
[Normal] 系统版本、任务方案、数据、模型和评测协议独立管理。候选模型先登记 candidate，通过冻结验收后更新推荐指针。评测数字由脚本计算，解释由模型生成；评测规则改变必须生成新版本。
[Heading 2] 数据和评测
[Normal] 原始数据通过文件权限或挂载保护；配方变化产生新 release，旧实验继续绑定旧数据。增强前划分，隔离近重复或同主体样本。在线增强记录实现和随机规则；评测输入保持确定。
[Normal] 调优使用训练与验证集，最终测试集独立。ROM、RAM、计算量和延迟分别定义口径，目标设备与运行时未知时不能宣称全部达标。不同评测基准分组比较，保留关键切片与历史回归。
[Heading 2] 外部问题闭环
[Normal] 反馈绑定具体模型和测评条件，记录场景、预期与实际、样例或引用、来源、严重程度和可上传范围。先复现并分类模型、数据、预处理、量化导出、运行配置或口径问题，再形成证据包供云端设计。
[Normal] 缺少样例时记录待验证假设，不能编造结果。可复现样例进入开发回归集；修复后同时评测问题切片与全局效果。用于反复调优的反馈样例不再作为未见最终测试。
[Heading 2] DOCX 状态与报告
[Normal] 数据库、事件和资产清单是事实来源。程序按模板生成系统状态与任务总览，记录版本、事件序号和时间；研究及复杂分析正文来自云端。单次报告与总览引用对应计划、运行和评测，更新时保留历史版本。
[Heading 1] 8 CLI 与实施路径
[Heading 2] 用户驱动方式
[Normal] 推荐 Typer 命令入口、prompt_toolkit 交互输入和 Rich 展示。支持自然语言新需求、方案微调与反馈，以及 /status、/plan、/approve、/feedback、/pause、/resume、/cancel、/budget、/export。聊天不能通过简单关键词误批准计划。
[Normal] CLI 连接本机控制服务，后台 worker 独立执行。退出 CLI 不停止训练，重连按事件序号补读。运行中的修订排队到安全边界；普通状态查询在本地完成。首版单机单用户，控制服务默认本机监听。
[Heading 2] 分阶段实现
[Normal] 先完成可安装工程、CLI、契约和持久化；再完成离线小数据闭环、方法池、数据模型版本和 DOCX 导出。随后接入真实研究模型、搜索、本地服务和 Codex，最后验证外部反馈迭代、故障恢复和真实业务验收。
[Normal] 离线演示使用确定种子的轻量 CPU 数据，明确标记 synthetic_demo。没有云端凭证或真实业务数据时继续独立开发，真实接入和业务验收保持待完成状态。
[Heading 2] 验收重点
[Normal] 检查子 Agent 内部自主循环是否保留；计划超范围是否返回规划；同一批多次实验是否减少规划调用；证据能否追溯与补读；批准是否随版本变化失效；退出重连及恢复是否重复提交；外部问题是否绑定正确模型；最终指标和文档是否一致。

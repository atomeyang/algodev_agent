## 验证口径

这不是预先编写的成功案例。用户发言由脚本模拟，Agent 回复、云端研究、工具调用、
编码和实验由真实运行时执行。脚本不提供算法实现、不伪造模型回复或指标。
创建任务时显式传入 TaskSpec，后续经过 CLI 同一 ControlClient.message 接口；
没有实际操纵终端 REPL 或浏览器 UI，因此不把它计为 UI 端到端验证。

研究/对话记录的模型为 `deepseek-flash`，编码请求模型取 Codex 配置快照
`gpt-6-astra`，本地辅助模型记录为 `qwen3.8-27b`。编码事件未回报服务端模型名
（`reported_model=null`），因此只能确认请求值，不能声称独立核实了底层模型身份。
配置名称不等于每个模型都已成功完成任务，以调用记录和实际产物为准。

使用 pseudo-MOS 双输出任务，不以历史 KonIQ MOS-only 成绩替代五类缺陷验收。
原始数据、历史产物和历史任务数据库不修改；每次尝试用独立任务与状态数据库。
这份历史测试基准已经暴露，即使复测达到数值门槛，也不构成新的独立业务验收。

冻结指标：PLCC >= 0.85、SRCC >= 0.85、defect_macro_f1 >= 0.85、
grade_agreement >= 0.90、hardcase_macro_f1 >= 0.85、ROM < 60 MB。
ROM 是 fp16 参数估算，不是手机安装包、运行内存或真机延迟。

每次任务预算：3 个研究轮次、每轮 12 个研究步骤、每轮最多 2 个候选、
8 次编码调用、2 次修复、9 个实验（预留最终测试）、40 epoch、
45 分钟、400,000 云端 token、8 次数据操作、240 个新增样本、4 个弱标注样本。
Codex 内部 token 另有使用记录，但目前不是受该云端 token 上限约束的硬配额。
各次执行是人工修复平台后的独立复测，不是 Agent 自己修复了平台运行时。

## 已确认的平台缺陷与修复

- 研究输出预算包含推理 token，8,192 上限导致正文反复截断。现默认 16,384、
  可配置且有上限；截断显式失败，要求返回更短的完整 JSON。
- 研究提示没有精确表达字符串列表等类型。现提供实际输出和候选 schema。
- 首轮 inspect_data 仅列发布版，返回空列表。现提供只读的训练/开发统计预览，
  不读取最终测试标签，不把原始图像路径传入该摘要。
- 模型猜测 `model_pool/...` 目录为可读源文件。现提供插件真实参考源码路径。
- 工具批次耗尽研究预算。现为最终计划与一次格式修复保留步骤，不增加总预算。
- 数据操作按单项看预算而非合计。现预检已知 count/limit 的合计与剩余预算，
  在研究上下文提供已用/预留预算，并说明每轮完整配方再次计费。
- resample 的 count 实际表示替换后的训练集大小，不是追加量；现明确该语义。
- 失败研究缺少落盘文档。现先保存失败结果、工具调用和未知项，再停止任务。
- 对话上下文缺少预算、次指标、停止原因及自己的控制方式。现补齐。
- 整份候选计划超长会被全部省略；现逐候选压缩，并显式给出严格比较表达式。
- 云端报告拼入离线模板，导致同份报告同时声称 live 和 offline；
  自主研究模式不再附上离线模板叙述，原始失败报告保持不变。
- 验证脚本区分开发/最终评测，不以最终评测补作开发成绩。
- Codex CLI 总进程返回 0，但内部命令全部因沙箱不可用而失败，原来仍按普通编码错误重试。
  现识别 namespace/Landlock 错误并传播 `blocked` 原因，不再消耗无效修复重试。
  此项在第四次任务运行中修改，已运行的父进程没有热加载；只通过了回归测试，
  **没有重新进行云端实测**，不能算本轮自主恢复成功。

最终全量平台回归测试：**264 passed in 130.29s**。执行命令：

```bash
env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=runtimes/agent_runtime/src:. /usr/local/bin/python3 -m pytest
```

新增回归在 `tests/test_live_validation_regressions.py`；真实对话驱动脚本为
`scripts/validate_iqa_dialogue.py`。测试通过只证明对应平台行为，不等于 GPU 算法达标。

`metrics._f1` 对没有正例的类给 0，`defect_macro_f1` 对五类求平均。
因此在保持这个开发测试集和指标定义不变时，该指标最高为 0.8，无法达到 0.85。
这是本数据与本实现的算术限制，不是 IQA 算法的理论性能上限。
仅补训练数据或模型弱标注不能补齐测试集白平衡正例，更不能据此证明真实白平衡能力。
需要另行取得独立、可信标注的覆盖数据并建立新的验收版本，不能在本轮偷偷换测试标准。

## 根因和仍存风险

1. **编码环境不可用。** 原始编码事件反复出现
   `bwrap: No permissions to create new namespace`，独立校验确认 `method.py` 不存在。
   无副作用兼容性探测也返回 `Sandbox(LandlockRestrict)`；没有绕过沙箱、改内核设置或全局配置。
   新增 blocked 分类不能修复宿主机隔离能力。
2. **基线计划参数无效。** `score_ckpt` 被写成字面文本
   `"plugin default (config.adapter_ckpt())"`，取代默认权重路径。独立核验确认 backbone
   和 adapter 文件均实际存在（299,864,852 / 300,984,314 字节）；
   文件存在不等于内容兼容性已验证，但足以否定“没有本地权重”的根因判断。
   下一轮应先解决参数解析，而不是直接判定整条深度模型路线不可用。
3. **失败根因传递不全。** 旧编码摘要传入“缺少实现”，却没有带入 bwrap 根因。
   第二轮报告据此错误地写“权重不存在/运行超时”，浪费了改方案和重复数据准备的预算。
   只靠自然语言解释错误，不能保证自主修复正确。
4. **辅助任务阻塞主流程。** 三次串行标注超时消耗约 15 分钟，没有熔断；
   随后的本地诊断也超时。数据/标注准备与编码、基线没有做到故障隔离。
5. **计划还不是完整可执行实验矩阵。** A0-A5 消融主要停留在文本，缺乏对应作业；
   v2 的累计扩增、不重叠子集等参数没有相应执行语义。
   v1 实现说明还把 `z=(score-50)/25` 的逆变换误写为 `100*(25*z+50)`，
   含多余 100 倍。代码未生成，因此这是尚未进入运行的方案错误。
6. **验收合同有双重来源。** IQA 插件仍以配置 PLCC/SRCC 0.90 生成额外失败项，
   与本任务合同 0.85 不一致。本次没有为取得达标而修改评测器，应在新验证前统一口径并回归。
7. **研究和对话存在过度推论。** 旧单模型结果或 oracle 诊断不是全体 IQA 算法性能上限；
   “flare 只有三个正例”影响覆盖与可靠性，不代表全部 hardcase 指标在实现中无法计算。
   `zero-ROM` 也不是树模型及其规则、参数的实测存储量。
8. **对话不是完整状态视图。** 最终回答称无法确认数据是否落盘，但 manifest 与弱标注记录
   已存在；又称评测切分未定，而 v1 已有 85 张固定开发协议。这说明需把数据、编码、
   协议证据加入结构化对话上下文，不能只给候选文本和预算数字。
9. **自动模式的交互仍可改进。** 首轮回复结尾仍询问是否需要确认协议后再编排，
   虽未实际阻塞 auto-process，但不符合无需重复审批的交互预期。明确指令路由通过，
   不等于任意复杂/歧义意图识别已验证；本次创建任务用了显式 TaskSpec。
10. **长时和复用能力未验证。** 未模拟服务重启、断电、多日持续运行、CLI 排版或 Web UI；
    跨任务记忆共享关闭，只证明本任务知识落盘，未证明跨任务检索使用和收益。

建议下次复测的先决条件：隔离环境可用性预检、真实资产及参数校验、
辅助标注超时熔断、消融作业化、数据配方语义校验，以及统一验收合同。
先获得可复现基线与一次新代码的开发评测，再测试按实测失败项驱动的第二轮改进。
真实业务验收还需要独立可信、覆盖五类缺陷的新增 holdout，不能重用本次已暴露基准冒充。
